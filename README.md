# AR บนกระดาษ (Image Tracking AR) — คู่มือติดตั้ง

หน้าเว็บนี้ใช้ไลบรารี **MindAR** (ฟรี, โอเพนซอร์ส) ทำงานผ่านเบราว์เซอร์มือถือ
โดยตรง ไม่ต้องติดตั้งแอปเพิ่ม เมื่อกล้องเจอภาพที่กำหนดไว้บนกระดาษ โมเดล 3D จะ
โผล่ขึ้นมาเองอัตโนมัติ

ชุดนี้มีไฟล์ครบพร้อมทดสอบแล้ว:
1. `assets/targets.mind` (ไฟล์ภาพเป้าหมายที่คอมไพล์แล้ว)
2. `assets/model.glb` (โมเดล 3D อาคาร)

หากต้องการเปลี่ยนภาพเป้าหมายหรือโมเดลเป็นของตัวเอง ให้ทำตามขั้นตอนที่ 1–3
ด้านล่างแล้วนำไฟล์ใหม่มาแทนที่ 2 ไฟล์นี้ (ใช้ชื่อไฟล์เดิม)

---

## ขั้นตอนที่ 1: เตรียมภาพที่จะพิมพ์ลงกระดาษ

เลือกภาพที่จะใช้เป็น "ตัวกระตุ้น" ให้ AR ปรากฏ ควรมีคุณสมบัติดังนี้:
- มีรายละเอียด ลวดลาย หรือคอนทราสต์เยอะ (หลีกเลี่ยงภาพสีพื้นเรียบๆ หรือลายซ้ำๆ
  เช่น ตารางหมากรุก เพราะระบบจะสับสน)
- เป็นภาพสี่เหลี่ยม ความละเอียดปานกลางพอ (ไม่ต้องสูงมาก)

## ขั้นตอนที่ 2: คอมไพล์ภาพเป็นไฟล์ .mind

1. เปิดเครื่องมือคอมไพล์ฟรีของ MindAR ที่
   **https://hiukim.github.io/mind-ar-js-doc/tools/compile/**
2. ลากภาพจากขั้นตอนที่ 1 เข้าไป
3. รอระบบประมวลผล แล้วกดดาวน์โหลดไฟล์ `targets.mind`
4. นำไฟล์นี้มาแทนที่ `assets/targets.mind` ในโฟลเดอร์นี้

## ขั้นตอนที่ 3: เตรียมไฟล์โมเดล 3D

นำไฟล์ `.glb` ที่แปลงจาก SketchUp มาวางแทนที่ `assets/model.glb`
(ไฟล์ต้องชื่อ `model.glb` พอดี หรือจะแก้ชื่อในโค้ด `index.html` บรรทัดที่มี
`src="./assets/model.glb"` ก็ได้)

### ปรับขนาด/ตำแหน่งโมเดล

สิ่งสำคัญที่ต้องเข้าใจก่อน: **ระนาบภาพเป้าหมายของ MindAR กว้าง 1 หน่วยเสมอ**
ไม่ว่าภาพจริงจะใหญ่แค่ไหน (ความสูงคิดตามสัดส่วนภาพ) จุดกึ่งกลางภาพคือ `0,0,0`
และแกน `+Z` ชี้พุ่งออกจากกระดาษ ดังนั้นโมเดลต้อง "ย่อ" ให้เหลือประมาณ 1 หน่วย
และต้อง "เลื่อน" ให้มาอยู่กึ่งกลางด้วย

โมเดลจาก SketchUp มักมีปัญหา 2 อย่างพร้อมกัน:
1. **ใหญ่เกินไปมาก** (หน่วยเป็นมิลลิเมตร/นิ้ว ตัวเลขจึงเป็นหลักพัน)
2. **ไม่ได้อยู่ที่จุดกำเนิด** ทำให้โผล่เยื้องออกไปนอกกระดาษ แม้ย่อขนาดถูกแล้ว

ของไฟล์ `model.glb` ปัจจุบัน วัดจากการถอดรหัส vertex ทั้ง 54,009 จุดโดยตรง:

| ค่า | X | Y | Z |
|---|---|---|---|
| ต่ำสุด | 76.33 | 0 | −964.14 |
| สูงสุด | 6032.80 | 1029.53 | 362.45 |
| ขนาด | 5956.47 | 1029.53 | 1326.58 |

> **ระวัง:** ค่า `min`/`max` ที่ ImageToStl.com เขียนกำกับไว้ในไฟล์ **ผิด** (สลับแกน
> Y กับ Z) โปรแกรมดูโมเดลบางตัวอ่านค่ากำกับนี้แล้วรายงานขนาดผิดตาม ต้องดูจาก
> ข้อมูล vertex จริงเท่านั้น

โมเดลเป็นแบบ **Y-up** (ฐานอยู่ที่ `Y=0`) แต่ระนาบ target ต้องการให้แกนขึ้นเป็น `+Z`
จึงต้องหมุน `90` องศารอบแกน X ไม่งั้นอาคารจะนอนหงายและจมลงไปหลังกระดาษ

```html
<a-gltf-model rotation="90 0 0" position="-0.5132 -0.0505 0"
              scale="0.000168 0.000168 0.000168" src="#model">
```

ที่มาของตัวเลข (คิดจากพิกัด **หลังหมุนแล้ว** เสมอ เพราะ A-Frame ใส่ `position`
หลังการหมุน — หมุน 90° รอบ X จะเปลี่ยนพิกัด `(x, y, z)` เป็น `(x, −z, y)`):
- `scale` = `1.0 / 5956.47` = `0.000168` → อาคารกว้างเท่าความกว้างภาพพอดี
- `position` X,Y = `-(จุดกึ่งกลางหลังหมุน × scale)` ดึงอาคารมาไว้กึ่งกลางภาพ
- `position` Z = `0` เพราะหลังหมุนแล้วฐานอาคารอยู่ที่ `Z=0` พอดี วางแนบบนกระดาษ

ผลลัพธ์ที่ได้: อาคารกิน X จาก `−0.500` ถึง `0.500`, Y จาก `−0.111` ถึง `0.111`
และสูงพ้นกระดาษขึ้นมา `0.173`

**ถ้าเปลี่ยนโมเดลใหม่** ให้วัดขนาดจริงก่อน (เปิดใน Blender หรือ
https://gltf-viewer.donmccurdy.com/) เช็คว่าเป็น Y-up หรือ Z-up แล้วคำนวณ:
`scale = 1.0 / ด้านที่ยาวที่สุดในระนาบกระดาษ` และ
`position = -(จุดกึ่งกลางหลังหมุน × scale)`

อยากให้อาคารใหญ่ขึ้น/เล็กลง ก็เปลี่ยนเลข `1.0` เป็นค่าอื่น (เช่น `0.6` = เล็กลง,
`1.5` = ล้นออกนอกภาพ) **แล้วอย่าลืมคำนวณ `position` ใหม่ด้วย** ไม่งั้นอาคารจะเยื้อง

### ประสิทธิภาพ (แก้อาการแลค)

ไฟล์ที่ได้จาก ImageToStl.com แตกอาคารออกเป็น **8,733 ชิ้นแยกกัน** ทั้งที่มีสามเหลี่ยม
รวมแค่ 37,742 อัน (เฉลี่ย 4 สามเหลี่ยมต่อชิ้น) แต่ละชิ้นคือ 1 draw call มือถือจึงต้อง
สั่งวาด 8,733 ครั้งทุกเฟรม นี่คือสาเหตุหลักของอาการแลค ไม่ใช่จำนวนสามเหลี่ยม

แก้โดยยุบชิ้นส่วนที่ใช้วัสดุเดียวกันเข้าด้วยกันด้วย
[glTF-Transform](https://gltf-transform.dev/):

```bash
npm install @gltf-transform/cli
npx gltf-transform dedup   in.glb  s1.glb
npx gltf-transform flatten s1.glb  s2.glb
npx gltf-transform join    s2.glb  s3.glb
npx gltf-transform weld    s3.glb  s4.glb
npx gltf-transform prune   s4.glb  out.glb
```

ผลที่ได้ (ตรวจแล้วว่าชุดสามเหลี่ยมและการจับคู่วัสดุเหมือนเดิมทุกอัน ไม่สูญเสียรูปทรง):

| | ก่อน | หลัง |
|---|---|---|
| draw calls | 8,733 | **21** |
| สามเหลี่ยม | 37,742 | 37,742 |
| vertices | 54,009 | 20,844 |
| ขนาดไฟล์ | 6.02 MB | **490 KB** |

ไฟล์ต้นฉบับ 6 MB ยังอยู่ในประวัติ git ถ้าต้องการย้อนกลับ

**ความหน่วง vs การสั่น:** MindAR ใช้ OneEuroFilter กรองการสั่น มีสองปุ่มปรับ

| ค่า | ค่าเริ่มต้น | ผลเมื่อเพิ่ม |
|---|---|---|
| `filterMinCF` | 0.001 | ตอบสนองไวขึ้น แต่**สั่นตลอดเวลา** |
| `filterBeta` | 1000 | ลดความหน่วงตอนขยับ โดยไม่เพิ่มการสั่นตอนอยู่นิ่ง |

เคยลองตั้ง `filterMinCF: 0.005` แล้วโมเดลสั่นตลอดเวลา จึงกลับมาใช้ค่าเริ่มต้น
**ถ้าจะแก้อาการตามช้า ให้เพิ่ม `filterBeta` ก่อนเสมอ อย่าไปเพิ่ม `filterMinCF`**

### คงโมเดลไว้เมื่อภาพหลุดเฟรม

ปกติ MindAR จะซ่อนโมเดลทันทีที่หาภาพไม่เจอ ทำให้พอก้มกล้องต่ำจนภาพหลุดเฟรม
อาคารก็หายไปเลย แก้ 2 ชั้น:

**ชั้นที่ 1 — `missTolerance: 10`** (เดิม 5) คือจำนวนเฟรมที่หาไม่เจอติดกันก่อนจะ
ถือว่าหลุด เพิ่มขึ้นเพื่อให้ทนต่อการบังชั่วขณะ

**ชั้นที่ 2 — แทนที่ `updateWorldMatrix`** ใน `index.html` ให้จำท่าล่าสุดไว้ แล้ว
ค้างโมเดลไว้ที่ท่านั้นแทนการซ่อน พอเล็งกลับไปเจอภาพก็กลับไปติดตามต่อเอง

> **ข้อจำกัดที่ต้องเข้าใจ:** MindAR ตรึงกล้องไว้ที่จุดกำเนิดแล้วขยับโมเดลแทน
> ช่วงที่ค้างไว้ โมเดลจึงติดอยู่กับ**หน้าจอ** ไม่ใช่ติดอยู่กับโต๊ะ — ขยับมือถือแล้ว
> โมเดลจะขยับตามไปด้วย ไม่ใช่การเดินดูรอบวัตถุแบบ AR จริง ซึ่งต้องใช้ world
> tracking (ARCore/ARKit) ที่ MindAR ไม่มี

โค้ดส่วนนี้แทนที่เมธอดภายในของ MindAR 1.2.5 **ถ้าอัปเกรดเวอร์ชัน ต้องตรวจสอบ
ก่อนว่า `updateWorldMatrix` ยังทำงานแบบเดิมอยู่หรือไม่**

### แอนิเมชัน

`model.glb` ปัจจุบันไม่มีแอนิเมชัน (`animations: 0`) จึงถอดไลบรารี `aframe-extras`
(~1.7 MB) ออกเพื่อให้โหลดเร็วขึ้นบนมือถือ ถ้าเปลี่ยนไปใช้โมเดลที่มีแอนิเมชัน
ให้เปิดบรรทัด `<script>` ของ `aframe-extras` ที่คอมเมนต์ไว้ในส่วน `<head>`
แล้วใส่ attribute `animation-mixer` กลับเข้าไปที่ `<a-gltf-model>`

### เปลี่ยนไฟล์ใน assets/ แล้วมือถือยังเห็นของเก่า (แคช)

GitHub Pages ส่งหัว `Cache-Control: max-age=600` มือถือจึงเก็บไฟล์เดิมไว้ 10 นาที
ถ้าเปลี่ยน `targets.mind` แล้วสแกนไม่ขึ้น สาเหตุมักเป็นเรื่องนี้ — เครื่องยังใช้
ไฟล์เก่าอยู่ จึงตามหา**ภาพเดิม** ในขณะที่คุณถือ**กระดาษใหม่**

วิธีแก้ที่ใช้ในโปรเจกต์นี้คือใส่เลขเวอร์ชันท้าย URL:

```html
mindar-image="imageTargetSrc: ./assets/targets.mind?v=3; ..."
<a-asset-item id="model" src="./assets/model.glb?v=3"></a-asset-item>
<div id="version">assets v3</div>
```

**ทุกครั้งที่เปลี่ยนไฟล์ใน `assets/` ให้บวกเลข `v` ขึ้น 1 ทั้ง 3 จุด** แล้ว push
เบราว์เซอร์จะถือว่าเป็นคนละไฟล์และโหลดใหม่ทันที

ป้ายเวอร์ชันมุมล่างของหน้าจอเริ่มต้นมีไว้ยืนยันด้วยตา — ถ้าเปิดแล้วยังเห็นเลขเก่า
แปลว่าตัว `index.html` เองยังติดแคช ให้ปิดแท็บทิ้งแล้วเปิดใหม่ หรือรอ 10 นาที

## ขั้นตอนที่ 4: พิมพ์ภาพลงกระดาษ

พิมพ์ **ภาพเดียวกันเป๊ะๆ** กับที่ใช้คอมไพล์ในขั้นตอนที่ 2 ลงกระดาษ A4
ไม่ควรใช้ภาพอื่นที่แค่คล้ายกัน เพราะระบบจับจุดสังเกตเฉพาะของภาพนั้นไว้แล้ว

## ขั้นตอนที่ 5: โฮสต์ผ่าน HTTPS แล้วทดสอบ

กล้องมือถือจะขอสิทธิ์ใช้งานได้ก็ต่อเมื่อหน้าเว็บเปิดผ่าน **HTTPS** เท่านั้น
(เช่นเดียวกับที่คุยกันไว้เรื่อง Cloudflare Tunnel) เมื่ออัปโหลดทั้งโฟลเดอร์
(`index.html` + โฟลเดอร์ `assets/`) ขึ้นโฮสต์แล้ว เปิดลิงก์จากมือถือ กดปุ่ม
"เปิดกล้อง" อนุญาตสิทธิ์กล้อง แล้วเล็งไปที่กระดาษที่พิมพ์ไว้

## ข้อควรระวัง

- **แสงในห้อง:** แสงน้อยเกินไปหรือสะท้อนแสงจ้าที่กระดาษจะทำให้กล้องจับภาพไม่ได้
  ควรทดสอบในสภาพแสงจริงของห้องเรียนก่อนใช้งานจริง
- **กระดาษยับหรือโค้งงอ:** ควรวางกระดาษให้เรียบที่สุด เพราะการบิดงอทำให้ภาพ
  ต้นแบบเพี้ยนไปจากที่คอมไพล์ไว้
- **ทดสอบก่อนใช้จริง:** ควรลองเปิดใช้งานบนมือถือทั้ง iOS และ Android อย่างน้อย
  เครื่องละ 1 รุ่นก่อนนำไปใช้กับนักเรียนทั้งห้อง
